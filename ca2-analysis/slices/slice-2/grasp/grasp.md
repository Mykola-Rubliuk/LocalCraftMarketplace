# GRASP justification — Slice 2

| Decision | Pattern | Justification | Alternative rejected |
|---|---|---|---|
| `OrderLine` checks and changes its own status | Information Expert | `OrderLine` knows its current status, which determines whether a change is allowed, so it can apply its own transition rules | `OrderFulfilmentService` checks and sets the status — transition rules would sit apart from the data they use |
| `OrderFulfilmentService` receives and coordinates the four `UC-04` operations | Controller | `OrderFulfilmentService` receives the `UC-04` operations and coordinates the objects needed to complete them, so `CustomerOrder` and `OrderLine` can focus on order rules without depending on `CustomerOrderRepository`, `Clock` or `CurrentUser` | `CustomerOrder` receives and coordinates the operations — it would mix order rules with workflow coordination and depend on outside collaborators |
| `CustomerOrder` recalculates its own status | Information Expert | `CustomerOrder` knows its lines and can check whether each one is closed, so it can recalculate its own status without `OrderFulfilmentService` needing that rule | `OrderFulfilmentService` checks the lines and sets the order status — the completion rule would sit apart from the order and its lines |
| `CustomerOrderRepository` finds and saves orders, instead of `CustomerOrder` saving itself | Pure Fabrication | `CustomerOrderRepository` is not a business concept and is added to find and save orders, so `CustomerOrder` can focus on order rules without depending on storage | `CustomerOrder` saves itself — it would mix order rules with storage and depend on how orders are stored |
| `CurrentUser` sits between `OrderFulfilmentService` and however sign-in works | Indirection | `CurrentUser` provides the signed-in user's identity, so `OrderFulfilmentService` does not depend directly on how sign-in works | Each operation that changes a line takes `volunteerId` as input — the contracts and SSD would change, and the design would have to ensure the ID belongs to the signed-in user (D-CA2-18) |
| `OrderFulfilmentService` gets the time from `Clock` and passes it to `OrderLine` | Low Coupling | `OrderLine` receives the time as a value, so it does not depend on `Clock` and can be tested with any time | `OrderLine` asks `Clock` for the time — `OrderLine` would depend on an outside collaborator |
